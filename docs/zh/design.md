# 工作原理

## 一切归监督进程所有，命令行只是客户端

一个守护进程持有运行时、进程和配置，并在回环地址上提供一个用令牌鉴权的 API。
`portable` 是这个 API 的第一个客户端。IDE 插件将是第二个，而且不需要为它补做任何东
西，因为不存在只能从命令行触及的能力。

这条规则值得抵御那种反复出现的诱惑 —— “这一小块直接做了算了”，因为为一件小事绕一趟
守护进程显得多余。每一次破例，日后都会变成插件里的一个缺口。

令牌不是走过场。这个 API 会启动进程，并且以该用户身份运行的任何东西都能访问它，包括
`npm install` 里的 postinstall 脚本。绑定回环地址挡得住其他机器，对本机上的东西却毫
无作用 —— 所以持有发现文件才是调用的凭据。

## Windows 上没有 php-fpm

FPM 是仅限 Unix 的 SAPI。Windows 版 PHP 提供的是 `php-cgi.exe`：给它一个地址它就说
FastCGI，而且**一次只服务一个请求**。它也无法派生自己的子进程：`PHP_FCGI_CHILDREN`
需要 `fork()`，而 Windows 没有。

所以并发就是 N 个端口上的 N 个独立进程，由路由器在它们之间分配。因此进程监督是这个
工具的核心，而不是围着它的管道工程。

有两个后果，不说明的话看起来像 bug：

- **工作进程退出是正常的。** `PHP_FCGI_MAX_REQUESTS` 让它在处理够一定数量的请求后
  主动退场，作为内存卫生。重新启动它是设计本身，不是故障恢复。
- **池的大小就是并发上限。** 四个工作进程时，第五个同时到达的请求要等。`php-cgi`
  内部没有队列来吸收它 —— 所以请求会在池内重试，而不是在落到一个正要退场的工作进程
  上时失败。

## 用 Caddy，不用 nginx

nginx 自己的文档说，它的 Windows 构建“只使用 `select()` 和 `poll()` 这两种连接处理
方式，因此不应期待高性能和可扩展性”，并且“被视为测试版”。

Caddy 是一个持续维护的原生二进制程序，带管理 API —— 于是添加一个站点只是对运行中的
服务器发一次 HTTP 调用，而不是一次会掐断所有在途连接的重启。它还自带一个本地证书颁
发机构，而正是这一点让 HTTPS 无需触碰机器的信任存储就能实现。

## 用 `*.localhost`，不用 `.test`

Windows 和 macOS 都会自己把 `.localhost` 下的一切解析到回环地址。不用往 hosts 里写
任何东西，也没有 DNS 服务器参与 —— 这正是“不需要管理员”这个承诺得以完整保留的原因。

`.test` 在没有 hosts 记录或 DNS 服务器的情况下哪儿也解析不到，而这两样都要花掉这个
工具并不具备的权限。

## 运行时来自其发布方，并经过校验

版本是对着发布方自己的索引解析的 —— php.net 的 `releases.json`、GitHub 的发布列表 ——
压缩包则与这些发布方给出的摘要比对。不匹配就删除文件：这里下载的一切随后都会被执行。

发布方不提供摘要的地方，会被记录并如实报告，而不是含糊过去。PostgreSQL 的 Windows
构建、Redis 的重新打包、PECL 的 Windows 扩展，以及 php.net 归档中的旧版本，都是未经
校验地到达的，工具每次都会说明。

测试用的样本数据是从发布方那里采集的，而不是手写的。手写样本只能证明解析器与它的作
者意见一致，而真实数据一再地不一致：Caddy 在一个看起来完全像 sha256 清单的文件里发
布 **sha512**；MariaDB 宣告的是普通 HTTP，并把摘要放在 `sha256sum` 键下；php.net 的
归档里，同一分支的不同版本把同一个编译器写作 `vc15` 和 `VC15`。

## 下载来的和机器上找到的运行时同等对待

这个工具装的 PHP，和机器上原本就有的 PHP，对监督进程来说是同一类东西。这不是退路：
需要预编译二进制里没有的扩展的人，正是靠这个才不被卡住；已经有可用 PHP 的机器，也正
是靠这个免于再下一个。

被接管的运行时只读不写。这个工具不会升级它、删除它，也不会往里装扩展。

## 一个目录，而且由你来选

运行时、配置、日志、数据库文件、Caddy 的证书颁发机构 —— 全在一个目录里。删掉它就等
于彻底卸载。

让这句话保持为真需要动手，而不只是整洁。Caddy 默认会把它的颁发机构和自动保存的配置
写到 `%AppData%` 下，完全在这份安装之外；两者都被重定向了，而自动保存被关掉了，因为
它同时也是陈旧配置卷土重来的路径。

位置之所以可选，是因为默认值并不总是能用：AppLocker 的常见配置会拒绝从用户配置目录
下执行程序，而这里下载的一切都是可执行文件。

## 无需提权的 HTTPS

Caddy 从一个本地证书颁发机构签发证书。若不加阻拦，它会自己把该机构的根证书装进机器
的信任存储，并警告说“可能会提示输入密码” —— 那是一次需要管理员权限的系统改动。

这被关掉了。`portable trust` 转而把根证书放进**当前用户**的存储，这不需要提权，而且
足够了：一份被坐在这台机器前的人所信任的证书，正是这件事应有的范围。

HTTPS 永远不会拖垮 HTTP。TLS 端口从空闲的端口中挑选，若一个都不空闲，就干脆不配置
TLS —— 监听在被占端口上的 TLS 会让 Caddy 整个起不来，而 HTTP 是产品，HTTPS 只是便利。

## 默认网络是坏的

每一次网络操作在遇到临时故障时都会重试，中断的下载从断点续传。这不是防御性的装饰：
在一个 TLS 握手会被中途重置的网络里，单次尝试多半失败，而把九十兆的压缩包从头再来
就意味着永远下不完。

过早结束的响应体也不会被当作下载完成。套接字关闭，读取返回空，而没有长度校验的话，
循环就会心满意足地停在一个少了最后三十兆的文件上 —— 对于那三个发布方不提供校验和的
运行时来说，下游没有任何人会察觉。
