# Начало работы

## Установка

В PowerShell, из обычного окна:

```powershell
irm https://raw.githubusercontent.com/dskripchenko/portable/main/install.ps1 | iex
```

Чтобы выбрать место или версию:

```powershell
$env:PORTABLE_INSTALL_DIR = 'D:\portable'
$env:PORTABLE_VERSION = '0.1.1'
irm https://raw.githubusercontent.com/dskripchenko/portable/main/install.ps1 | iex
```

Именно через `iex`, а не «скачать и запустить», и это не вкусовщина: под
политикой `Restricted` — умолчание на нетронутой машине и чаще всего
навязанное на управляемой — файл `.ps1` с диска запускаться отказывается, а
строка выполняется.

Установщику не нужно ничего, чего нет в стоковой Windows. Он сверяет бандл с
контрольной суммой, опубликованной рядом, один раз запускает его прежде чем
сказать, что всё получилось, и отказывается ставить поверх существующей
копии — для этого есть `portable upgrade`.

### Запуск откуда угодно

Прописать каталог установки в PATH можно, и больше ничего не требуется: лаунчер
находит свой интерпретатор и свои настройки по тому, где лежит сам, а не по
тому, где стоите вы. `portable site add demo .` тогда означает каталог, в
котором вы находитесь, и `portable run` выполняется там же.

Этот каталог при этом никем не удерживается. Демон и всё, что он ведёт, стоят в
собственной папке установки: процесс держит свой рабочий каталог открытым, а на
Windows удерживаемую папку нельзя ни удалить, ни переименовать — и проводник
скажет лишь, что она «открыта в другой программе».

**PATH не трогается.** Обещание инструмента в том, что удаление его каталога
убирает его целиком, а запись в PATH была бы исключением. Если она всё же
нужна — `$env:PORTABLE_ADD_TO_PATH = '1'`; это единственное, что установщик
пишет вне каталога установки.

### Если заблокирован сам PowerShell

Бывает, что зажимают не инструмент, а PowerShell: AppLocker и WDAC переводят
его в Constrained Language Mode, где отказываются работать даже `Get-FileHash`
и `Expand-Archive`. Ничего из написанного выше не обязательно. Из `cmd`:

```bat
curl -fsSL -o portable.zip https://github.com/dskripchenko/portable/releases/latest/download/portable-windows-x64.zip
curl -fsSL -o portable.zip.sha256 https://github.com/dskripchenko/portable/releases/latest/download/portable-windows-x64.zip.sha256

certutil -hashfile portable.zip SHA256
type portable.zip.sha256

tar -xf portable.zip
```

Сверьте два хеша глазами и запустите `portable.cmd` из появившейся папки. Ни
один скрипт при этом не исполняется, поэтому ни политика выполнения, ни режим
языка, ни правила для скриптов сюда не относятся. `curl.exe`, `tar.exe` и
`certutil.exe` лежат в `System32` начиная с Windows 10 1803.

Ключ `-f` важен: без него curl сохранит страницу «не найдено» как архив и
отчитается об успехе, а `tar` потом пожалуется на архив вместо адреса.

### Или вручную

Скачайте `portable-x86_64-pc-windows-msvc.zip` со страницы
[релизов](https://github.com/dskripchenko/portable/releases) и распакуйте куда
угодно — в папку на рабочем столе, на второй диск, на флешку. Устанавливать
нечего и установщика нет.

Бандл несёт собственный Python. Инструмент, чья работа — ставить рантаймы на
машину, где их нет, не может разумно требовать один из них заранее, а на Windows
его нет вовсе: то, что выглядит как `python`, это ярлык, открывающий Microsoft
Store.

```powershell
cd C:\portable
.\portable.cmd version
```

Запускайте из обычного окна PowerShell. Если что-то когда-либо попросит прав
администратора — это ошибка, сообщите о ней.

## Выберите, где он будет хранить данные

```powershell
.\portable.cmd home                    # где и чем это решено
.\portable.cmd home set D:\portable    # с этого момента — туда
.\portable.cmd home set --beside       # рядом с лаунчером, чтобы ехало вместе с ним
```

По умолчанию — `%LOCALAPPDATA%\portable`. На управляемой машине это умолчание
бывает не просто неудобным, а нерабочим: AppLocker в типовых конфигурациях
запрещает запуск из профиля пользователя — туда и ставится софт без прав
администратора, ради чего правило и существует, — а всё, что здесь скачивается,
это исполняемые файлы. Там, где правило действует, до переноса каталога не
запустится ничего.

`--beside` предназначен для флешки. Он хранит слово, а не сегодняшний путь,
поэтому бандл продолжает работать при смене буквы диска.

## Запуск

```powershell
.\portable.cmd up
```

Запускается супервизор, которому принадлежит всё остальное. Он переживает
закрытие терминала и IDE. Перезагрузку — нет, и это сделано намеренно: пережить
её означало бы запись в автозагрузку, а таких инструмент не делает.

## Поднять сайт

```powershell
.\portable.cmd install php
.\portable.cmd install caddy
.\portable.cmd site add demo C:\projects\demo
```

Откройте `http://demo.localhost`. Файл hosts не правился, DNS-сервер не
участвовал: Windows сама разрешает всё внутри `.localhost` в петлевой адрес.

Если проект держит фронт-контроллер в `public/` — Laravel, Symfony и почти все
остальные — обслуживаться будет именно он, и инструмент об этом скажет. Иначе
направление сайта в корень репозитория отдавало бы исходники приложения по HTTP
вместе с `.env`, причём с виду это выглядит просто как «не работает». Флаг
`--exact` берёт путь буквально.

Версия PHP закрепляется за сайтом через `--php 8.2`; без него сайт следует за
новейшей. Несколько версий работают одновременно, у каждой свой пул воркеров.

## HTTPS

```powershell
.\portable.cmd trust
```

Сайты отдаются и по TLS, из удостоверяющего центра, который Caddy держит
локально. `trust` кладёт корень этого центра в **ваше** хранилище сертификатов,
а не в машинное — для последнего нужны права администратора.

Windows покажет диалог подтверждения. Это спрашивает Windows, а не инструмент, и
обхода тут быть не должно.

Firefox держит собственное хранилище и продолжит предупреждать. Он читает
системное, только если в `about:config` включён
`security.enterprise_roots.enabled`, — а это настройка в вашем профиле, и менять
её не дело инструмента.

## Добавить базу

```powershell
.\portable.cmd install postgres
.\portable.cmd service add postgres
```

Она поднимется на `127.0.0.1:5432`, пользователь `postgres`, без пароля — и
только на петлевом адресе, потому что доверительная аутентификация на порту,
доступном по сети, — это способ, которым ноутбук на конференционном wifi
становится чужим.

`service remove` останавливает её и **сохраняет данные**. Повторное добавление
продолжает с того же места.

`mariadb` и `redis` работают так же, на 3306 и 6379.

## Node и прочие инструменты

```powershell
.\portable.cmd install node
.\portable.cmd run npm install
```

`portable run` добавляет установленные рантаймы в PATH только для этой одной
команды. Системный PATH не меняется. Если нужны настройки на всю сессию
оболочки — их печатает `portable env`.

## Остановка

```powershell
.\portable.cmd down
```

Останавливается всё: роутер, воркеры PHP, базы. К моменту возврата команды порты
свободны.

Чтобы убрать инструмент полностью, удалите каталог, где он хранит данные
(`portable home` скажет, где это), и распакованную папку. Больше ничего нет: ни
ключей реестра, ни служб, ни правок PATH.
