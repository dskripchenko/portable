# Команды

У каждой команды есть `--json`, а также `--home PATH`, чтобы разово обратиться к
другой установке. `portable help` печатает сокращённый вариант этой страницы.

## Супервизор

| | |
|---|---|
| `portable up` | Запустить супервизор. Всё остальное говорит с ним. |
| `portable down` | Остановить его и всё, что он держит. |
| `portable status` | Что работает, на каком порту и почему ничего не обслуживается, если это так. |
| `portable version` | Сборка, интерпретатор за ней, где хранятся данные и версия работающего демона. |
| `portable help` | Все команды по назначению, с примером на каждую. |
| `portable upgrade [--check]` | Заменить инструмент новейшим выпуском. |

`status` и `version` работают и без запущенного демона — то есть в том
состоянии, в котором вопрос обычно и возникает.

`upgrade` скачивает новейший выпуск, сверяет его с дайджестом, опубликованным
рядом, и один раз запускает — прежде чем тронуть что-либо существующее. Только
после этого прежняя установка отодвигается, а новая занимает её место, причём
делает это системная оболочка скриптом вне обеих: Windows не переименует
каталог, внутри которого работает программа.

Прежняя версия остаётся рядом с новой, пока вы её не удалите, а если обмен не
удался — возвращается на место. Инструмент, который просто устарел, куда лучше
отсутствующего.

## Рантаймы

| | |
|---|---|
| `portable available <рантайм>` | Что издатель предлагает сейчас, с пометкой установленного. |
| `portable available php 8.3` | Эта ветка, включая вытесненные патчи из архива php.net. |
| `portable install <рантайм> [версия]` | Ветка (`8.4`), точная версия (`8.4.24`) или `latest`. |
| `portable install php --from C:\php` | Принять PHP, уже имеющийся на машине. |
| `portable runtimes` | Что установлено. |
| `portable update [--install]` | Новые выпуски на той же линии, что и установленное. |
| `portable uninstall <рантайм> <версия>` | Удалить версию и вернуть диск. |

Устанавливаются: `php`, `caddy`, `node`, `postgres`, `mariadb`, `redis`.

**Версии ставятся рядом, а не поверх.** Всё, что закреплено за старой,
продолжает работать — ради чего и существует `uninstall`.

**Обновление не покидает свою линию** — новейший `8.4.x` для 8.4, но не 8.5.
Смена ветки PHP приносит устаревания каждому сайту, который ничего не закреплял,
а каталог данных PostgreSQL принадлежит создавшему его мажору: 17 не поднимется
на файлах 18. Пересечение линии делается указанием версии.

**Принятый рантайм только читается.** Инструмент не станет его обновлять,
удалять или ставить в него расширения. Удалить PHP, которым управляет чужой
установщик, было бы странным поступком.

## Сайты

| | |
|---|---|
| `portable site add <имя> [путь]` | Отдавать каталог на `<имя>.localhost`. |
| `portable site add <имя> <путь> --exact` | Взять путь буквально, не ища внутри `public/`. |
| `portable site add <имя> <путь> --php 8.2` | Закрепить версию. По умолчанию — новейшая установленная. |
| `portable site list` | Сайты и их адреса. |
| `portable site remove <имя>` | Перестать отдавать. |
| `portable port 8888` | Порт, на котором отдаются сайты. `auto` возвращает к попыткам 80, затем 8080. |
| `portable trust` | Доверять локальному удостоверяющему центру, чтобы `https://` перестал предупреждать. `--forget` отменяет. |

Выбранный порт — **единственный**, который пробуется. Откат на 8080 после
просьбы о 8888 поставил бы сайт по адресу, который вы не выбирали и о котором вам
не сказали, — а выбирают порт как раз потому, что умолчания не подошли.

## Несколько версий одновременно

Все установленные версии PHP могут обслуживать одновременно. У каждой свой пул
воркеров и свой `php.ini`; сайты выбирают между ними через `--php`, а сайт,
который ничего не закрепил, следует за новейшей.

С базами то же самое, но по экземплярам, а не по версиям: `--name` даёт второму
свой каталог данных и порт, а `--version` закрепляет, какую из установленных
сборок он запускает.

## Расширения PHP

| | |
|---|---|
| `portable ext list` | Что несёт эта сборка и что из этого загружено. |
| `portable ext enable <имя>` | Загрузить то, что в сборке уже есть. |
| `portable ext disable <имя>` | Перестать загружать. |
| `portable ext install <имя> [версия]` | Скачать то, чего в сборке нет: `xdebug`, `redis`, `imagick`. |

У всех есть `--php 8.3` — выбрать, к какому установленному PHP это относится.

Windows-сборка PHP несёт каждое поддерживаемое расширение отдельной DLL: все на
месте, ни одно не загружено, — поэтому `enable` это строчка в `php.ini`, а не
скачивание. `install` — скачивание, подобранное под ветку PHP этой сборки, её
потокобезопасность, компилятор и архитектуру; все четыре должны совпасть, иначе
расширение молча не загрузится.

Смена расширения заменяет воркеров, потому что каждый `php-cgi` читает `php.ini`
один раз при старте. Сам `php.ini` пишется при установке PHP и больше не
перегенерируется: ваши правки в нём переживают всё, что здесь описано.

Если у новейшего выпуска расширения нет сборки под ваш PHP — назовите более
старый. Xdebug 3 под PHP 7.2 не собирается и не будет; xdebug 2.9.8 собирается.

## Базы данных

| | |
|---|---|
| `portable service add <вид>` | Запустить `postgres`, `mariadb` или `redis`. |
| `portable service list` | Что работает и как подключиться. |
| `portable service remove <имя>` | Остановить. **Данные сохраняются.** |

Каждая слушает только петлевой адрес. `--port` и `--name` нужны, когда хочется
второй экземпляр или непринятый порт.

Каталог данных инициализируется один раз, у PostgreSQL — с фиксированной
сортировкой `C`: база, чья сортировка следует за региональными настройками
машины, сортирует иначе, чем продакшен, и выясняется это в тесте, который у
одного человека проходит.

## Всё остальное

| | |
|---|---|
| `portable run <команда>` | Выполнить что-то с установленными рантаймами в PATH — только для этой команды. |
| `portable env` | Напечатать настройки, которые понадобились бы оболочке, вместо того чтобы что-то менять. |
| `portable home` | Где всё хранится и чем это решено. |
| `portable home set <путь>` | Хранить в другом месте. `--beside` — рядом с лаунчером. |
| `portable home clear` | Вернуться к умолчанию. |

`portable run node --version` скажет, если запускает Node, которым инструмент не
управляет, — системный, найденный в PATH. Иначе на этом легко потерять двадцать
минут.
