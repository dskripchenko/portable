# Команды

У каждой команды есть `--json`, а также `--home PATH`, чтобы разово обратиться к
другой установке. `portable help` печатает сокращённый вариант этой страницы.

## Супервизор

| | |
|---|---|
| `portable up` | Запустить супервизор. Всё остальное говорит с ним. |
| `portable down` | Остановить его и всё, что он держит. |
| `portable status` | Что работает, на каком порту и почему ничего не обслуживается, если это так. |
| `portable version` | Сборка, интерпретатор за ней, где хранятся данные и версия работающего демона. |
| `portable help` | Все команды по назначению, с примером на каждую. |
| `portable dash` | Полноэкранная панель: процессы, сайты, базы и живые логи вместе. |
| `portable shell` | Выполнять команды подряд, не набирая каждый раз `portable`. |
| `portable logs [имя] [-f]` | Что пишут поднадзорные процессы. Имя целиком или его начало. |
| `portable upgrade [--check]` | Заменить инструмент новейшим выпуском. |

`status` и `version` работают и без запущенного демона — то есть в том
состоянии, в котором вопрос обычно и возникает.

`upgrade` скачивает новейший выпуск, сверяет его с дайджестом, опубликованным
рядом, и один раз запускает — прежде чем тронуть что-либо существующее. Только
после этого прежние файлы отодвигаются, а новые занимают их место.

Сама папка при этом не переименовывается, и это намеренно: Windows отказывается
переименовать каталог, который является для какого-то процесса текущим, а при
обновлении он обычно им и является — в нём стоит оболочка, где вы набрали
команду. Переезжает только содержимое. Всё, что в папке не относится к бандлу,
остаётся на месте, включая каталог данных, если его туда положил
`home set --beside`.

Прежняя версия остаётся рядом с новой, пока вы её не удалите, а если обмен не
удался — всё возвращается на место. Инструмент, который просто устарел, куда
лучше отсутствующего.

`logs php -f` следит сразу за всеми воркерами всех версий PHP: имя совпадает и
целиком, и по началу — именно так о пуле и думают, а не как о `php-8.4.24-1`
… `-4`. Строки помечены тем, кто их написал, и раскрашены по тому, насколько
тревожно они звучат.

Файлы читаются напрямую, поэтому это работает и при остановленном демоне — а
именно тогда вопрос обычно и возникает.

У `shell` нет автодополнения по Tab. `readline` — Unix-расширение, которого нет
в Windows-сборках CPython, поэтому дополнение потребовало бы библиотеки, а у
бандла намеренно нет зависимостей. История и стрелки работают средствами
консоли.

`dash` показывает всё сразу, потому что ответы обычно нужны вместе: какой воркер
умер — вопрос к логу, вернулся ли он — к таблице процессов, а читать их по
очереди значит переключаться между двумя командами, пока наблюдаемое движется.

В неё же и печатают. Команды вводятся снизу, без `portable` перед ними, а
набранное и ответ ложатся в тот же поток, что и вывод самих служб, в порядке
происходившего — именно это превращает «я добавил сайт, и вот что появилось в
логе» в то, что можно прочитать, а не восстановить. Стрелки возвращают
набранное раньше; по ходу набора есть подсказки.

`F10` выходит, `F5` обновляет, `F2` ставит лог на паузу. Функциональные — потому
что буквы теперь принадлежат командной строке. `dash php` следит внизу только за
PHP. Выбор базы в её таблице и Enter открывают приглашение к ней.

В правом верхнем углу — лицо, и отвечает оно на тот же вопрос, что и блок
рядом: всё ли в порядке. Только издалека: смену фигуры видно через комнату,
строку текста — нет.

```
|\---/|      |\---/|      |\---/|      |\---/|
| o o |      | o o |      | ^ ^ |      | x x |
|  >_ |      |  .. |      | \_/ |      |  >! |
'-----'      '-----'      '-----'      '-----'
  занят      ждёт ответа   получилось    ошибка

|\---/|      |\---/|      |\---/|      |\---/|
| o o |      | - - |      | O O |      | - - |
|  >_ |      |  >_ |      |  >o |      |  zZ |
'-----'      '-----'      '-----'      '-----'
  покой       моргает      демон исчез  не поднят
```

Он показывает состояния, а не занятия. Какая команда идёт, уже написано на
полосе ниже — по имени и с отсчётом секунд; лицо, повторяющее это, сказало бы
то же самое хуже, а меняющееся на каждое действие перестало бы значить
«посмотри сюда».

- **ждёт ответа** — команда пять секунд ничего не сказала. Большая часть
  установки уходит на ожидание чужого хоста, и полоса крутится одинаково: это
  разница между медленной закачкой и тридцатисекундным таймаутом соединения,
  который выглядит зависанием.
- **получилось** и **ошибка** — чем кончилась набранная вами команда. Ошибка
  держится до следующего успеха, а не гаснет по таймеру: лицо, которое веселеет
  само, сообщает о ходе времени, а не о состоянии чего-либо.
- **демон исчез** — супервизор был секунду назад, и его никто не просил уйти.
  Это новость; а то, что он не поднят, когда вы открыли экран, — нет.
- **моргает** — раз в двадцать пять секунд, на мгновение. Тот же довод, что и у
  индикатора занятости: неподвижная картинка не отличает внимание от
  зависшего процесса.

Это та же фигура, что и в логотипе, и она нарочно из ASCII: терминал без шрифта
для псевдографики покажет квадратики, а маскот из квадратиков делает экран
сломанным ровно тогда, когда должен успокаивать. Ниже двадцати четырёх строк он
уходит вместе с тремя строками рядом: строки здесь — дефицитное, и картинка
ценой строки таблицы того не стоит.


Несколько команд оттуда не выполняются, и каждая говорит почему: `upgrade`
заменяет папку, из которой запущен экран, `purge` задаёт вопрос, который экран
задать не может, а `logs -f` — это то, что нижняя панель уже делает.

Это единственная часть инструмента с библиотеками помимо стандартной. Их четыре,
вложены в бандл: `textual` называет ещё шесть, за которыми здесь ничто не
тянется, а везти их — это четыре с половиной мегабайта лексеров подсветки для
экрана, который ничего не подсвечивает. Тест блокирует эти импорты и запускает
панель, чтобы так и оставалось.

## Рантаймы

| | |
|---|---|
| `portable available <рантайм>` | Что издатель предлагает сейчас, с пометкой установленного. |
| `portable available php 8.3` | Эта ветка, включая вытесненные патчи из архива php.net. |
| `portable install <рантайм> [версия]` | Ветка (`8.4`), точная версия (`8.4.24`) или `latest`. |
| `portable install php --from C:\php` | Принять PHP, уже имеющийся на машине. |
| `portable runtimes` | Что установлено. |
| `portable update [--install]` | Новые выпуски на той же линии, что и установленное. |
| `portable uninstall <рантайм> <версия>` | Удалить версию и вернуть диск. |

Устанавливаются: `php`, `caddy`, `node`, `postgres`, `mariadb`, `redis`.

**Версии ставятся рядом, а не поверх.** Всё, что закреплено за старой,
продолжает работать — ради чего и существует `uninstall`.

**Обновление не покидает свою линию** — новейший `8.4.x` для 8.4, но не 8.5.
Смена ветки PHP приносит устаревания каждому сайту, который ничего не закреплял,
а каталог данных PostgreSQL принадлежит создавшему его мажору: 17 не поднимется
на файлах 18. Пересечение линии делается указанием версии.

**Принятый рантайм только читается.** Инструмент не станет его обновлять,
удалять или ставить в него расширения. Удалить PHP, которым управляет чужой
установщик, было бы странным поступком.

## Сайты

| | |
|---|---|
| `portable site add <имя> [путь]` | Отдавать каталог на `<имя>.localhost`. |
| `portable site add <имя> <путь> --exact` | Взять путь буквально, не ища внутри `public/`. |
| `portable site add <имя> <путь> --php 8.2` | Закрепить версию. По умолчанию — новейшая установленная. |
| `portable site list` | Сайты и их адреса. |
| `portable site remove <имя>` | Перестать отдавать. |
| `portable port 8888` | Порт, на котором отдаются сайты. `auto` возвращает к попыткам 80, затем 8080. |
| `portable trust` | Доверять локальному удостоверяющему центру, чтобы `https://` перестал предупреждать. `--forget` отменяет. |

Выбранный порт — **единственный**, который пробуется. Откат на 8080 после
просьбы о 8888 поставил бы сайт по адресу, который вы не выбирали и о котором вам
не сказали, — а выбирают порт как раз потому, что умолчания не подошли.

`trust` кладёт корень локального центра в **ваше** хранилище — единственное
доступное без прав администратора — и пишет `conf/ca-bundle.pem`: собственные
доверенные корни этой машины вместе с этим корнем. На него указывается каждый
установленный PHP.

PHP, curl и Node читают свои списки, а не системное хранилище. Именно поэтому
сайт открывается в Chrome зелёным, а `file_get_contents('https://api.localhost')`
из кода того же сайта падает на проверке сертификата. `portable run` и
`portable env` передают этот же файл curl и Node.

Системные корни там намеренно: набор из одного лишь локального центра заставил
бы PHP доверять `api.localhost` и отвергать все публичные сертификаты. Если
корни машины собрать не удалось, не пишется ничего, и `trust` об этом говорит —
вместо того чтобы оставить PHP не доверяющим никому.

Ради этого не нужно запускать `trust` заново: супервизор пишет файл при старте,
если центр есть, а файла нет или он старше центра.

Если 443 и 8443 оба заняты, слушатель HTTPS не поднимается вовсе — на HTTP это
не влияет. `status` скажет об этом и назовёт, кто их держит.

## Несколько версий одновременно

Все установленные версии PHP могут обслуживать одновременно. У каждой свой пул
воркеров и свой `php.ini`; сайты выбирают между ними через `--php`, а сайт,
который ничего не закрепил, следует за новейшей.

С базами то же самое, но по экземплярам, а не по версиям: `--name` даёт второму
свой каталог данных и порт, а `--version` закрепляет, какую из установленных
сборок он запускает.

`purge` — это то, что снова делает правдой «удалите папку, и его нет». Вне неё
может оказаться четыре вещи: каталог данных, запись в PATH, доверенный
сертификат и копия, оставленная обновлением, — и о трёх никто не вспомнит.
Команда находит то, что действительно есть, перечисляет с размерами, спрашивает
и убирает.

Саму папку она не удаляет: код выполняется изнутри неё, а Windows не удалит
каталог с работающей программой. После неё эта папка — единственное, что
осталось.

## Расширения PHP

| | |
|---|---|
| `portable ext list` | Что несёт эта сборка и что из этого загружено. |
| `portable ext enable <имя>` | Загрузить то, что в сборке уже есть. |
| `portable ext disable <имя>` | Перестать загружать. |
| `portable ext install <имя> [версия]` | Скачать то, чего в сборке нет: `xdebug`, `redis`, `imagick`. |

У всех есть `--php 8.3` — выбрать, к какому установленному PHP это относится.

Windows-сборка PHP несёт каждое поддерживаемое расширение отдельной DLL: все на
месте, ни одно не загружено, — поэтому `enable` это строчка в `php.ini`, а не
скачивание. `install` — скачивание, подобранное под ветку PHP этой сборки, её
потокобезопасность, компилятор и архитектуру; все четыре должны совпасть, иначе
расширение молча не загрузится.

Смена расширения заменяет воркеров, потому что каждый `php-cgi` читает `php.ini`
один раз при старте. Сам `php.ini` пишется при установке PHP и больше не
перегенерируется: ваши правки в нём переживают всё, что здесь описано.

Если у новейшего выпуска расширения нет сборки под ваш PHP — назовите более
старый. Xdebug 3 под PHP 7.2 не собирается и не будет; xdebug 2.9.8 собирается.

## Базы данных

| | |
|---|---|
| `portable service add <вид>` | Запустить `postgres`, `mariadb` или `redis`. |
| `portable service list` | Что работает и как подключиться. |
| `portable service cli [имя]` | Приглашение к одной из них — `psql`, `mariadb`, `redis-cli`. |
| `portable service remove <имя>` | Остановить. **Данные сохраняются.** |

Несколько версий одной базы работают одновременно: каждая — отдельный сервис со
своим именем, версией и портом, а `service cli <имя>` выбирает по имени, а не по
версии. `service list` показывает версию, на которой сервис работает на самом
деле, — она не всегда та, что запрошена: сервис, объявленный без версии, следует
за самой новой установленной.

```powershell
portable service add postgres --name pg16 --version 16 --port 5432
portable service add postgres --name pg17 --version 17 --port 5433
portable service cli pg17
```

`service cli` запускает клиент из того же архива, что и сервер, направленный на
нужный порт по TCP, — и клиент именно работающей версии, а не самой новой на
машине. Все три записывают одни и те же три факта — хост, порт,
пользователь — тремя разными способами, а клиент MariaDB в Windows ещё и
предпочитает именованный канал, когда хост выглядит локальным, — сервер здесь
такого не предлагает. Имя можно не указывать, если база одна.

В dash выберите базу в её таблице и нажмите Enter: экран отходит в сторону,
клиент получает настоящий терминал, а экран возвращается, когда вы из клиента
выйдете. `--json` печатает команду вместо запуска — это то, что нужно плагину
редактора.

Каждая слушает только петлевой адрес. `--port` и `--name` нужны, когда хочется
второй экземпляр или непринятый порт.

Каталог данных инициализируется один раз, у PostgreSQL — с фиксированной
сортировкой `C`: база, чья сортировка следует за региональными настройками
машины, сортирует иначе, чем продакшен, и выясняется это в тесте, который у
одного человека проходит.

## Всё остальное

| | |
|---|---|
| `portable run <команда>` | Выполнить что-то с установленными рантаймами в PATH — только для этой команды. |
| `portable env` | Напечатать настройки, которые понадобились бы оболочке, вместо того чтобы что-то менять. |
| `portable home` | Где всё хранится и чем это решено. |
| `portable home set <путь>` | Хранить в другом месте. `--beside` — рядом с лаунчером. |
| `portable proxy` | Через что идёт всё исходящее и кто это решил. |
| `portable proxy set <url>` | Через него пойдут закачки, каталоги и проверки обновлений. |
| `portable proxy clear` | Снова следовать окружению. |
| `portable home clear` | Вернуться к умолчанию. |
| `portable path` | Прописан ли инструмент в PATH. |
| `portable purge` | Убрать всё, что инструмент положил вне своей папки. |
| `portable path add` | Прописать — **вам**, без администратора. `remove` отменяет. |

`proxy` — для машины, которой прокси нужен, а в окружении он не прописан.
`HTTPS_PROXY` учитывается как и раньше; заданный здесь его перекрывает: два
источника одного ответа означают, что половину времени действует не тот, и
ничто не говорит какой.

```powershell
portable proxy set http://proxy.corp:3128
portable proxy set http://bob:secret@proxy.corp:3128    # если нужен пароль
```

Действует на всё скачиваемое: рантаймы, расширения PHP, каталоги издателей, API
GitHub и проверку обновлений. Схема — `http://` даже для прокси, который ходит
за `https`: этот адрес описывает, как добраться до прокси, а не как он доберётся
до цели. SOCKS отклоняется сразу, а не принимается и падает потом: с прокси здесь
разговаривает стандартная библиотека Python, а она умеет только HTTP-прокси.

Пароль хранится как есть и не печатается: `proxy` и `version` показывают
`bob:***@`, чтобы он не уехал в присланный отчёт об ошибке.


`path add` пишет в `HKEY_CURRENT_USER` — ваше собственное окружение, для
которого прав администратора не нужно. Машинный PATH лежит в другом месте и не
трогается никогда; возможности его тронуть нет.

Это единственное, что инструмент пишет вне своего каталога, — поэтому он делает
это по вашей команде, а не при установке, и поэтому `path remove` возвращает всё
ровно как было.

`portable run node --version` скажет, если запускает Node, которым инструмент не
управляет, — системный, найденный в PATH. Иначе на этом легко потерять двадцать
минут.
